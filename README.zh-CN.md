本项目呈现 **Qiushi Engine 围绕二元域上 3 × 3 矩阵乘法开展的长程自主数学研究**。
研究形成了**精确双线性复杂度至少为 21**的结构性证明，并公开与之相连的研究轨迹、
中间成果、程序和证书，让读者既能检查结论，也能理解证明如何逐步形成。

Qiushi Engine 独立自主地完成数学研究，从形成研究路线、开展计算实验、检验与修正推论，
到构建完整证明。报告讲清证据与研究记忆如何持续积累、如何推动表示方式的改变，
以及系统怎样从寻找算法，转向以代数结构解释 20 次算法为何不可能存在。
开放材料不仅呈现最终成果，也为研究、复用和继续发展这一长程自主科研过程提供依据。

## 问题与贡献

直接计算需要 27 次乘法，已有双线性算法只需 23 次。构造算法给出上界；
证明下界则必须排除规定模型内所有更短的算法，而不只是搜索过的候选。
这里一次计数的乘法，是“第一输入的一个线性组合”乘以“第二输入的一个线性组合”。
二元域只有 0 和 1，加法按模二计算。

这是精确代数复杂度问题，不是 CPU 指令数或 GPU 吞吐量测试。
矩阵虽小，可能的分解及其因子之间的关系仍极其复杂。
本研究的意义在于，把末段候选枚举转化为可解释的代数矛盾。

关键不只是计算排除了候选，而是解释了它们为什么不可能：
有限约束迫使假设中的 20 项分解出现三个可逆第一因子；
饱和展平的代数恒等式却证明，两个可逆第一因子都不可能同时出现。
其中秩型 (16, 1, 3) 指 16 个秩一、1 个秩二、3 个秩三的第一因子矩阵，
秩之和 16 + 2 + 9 = 27 恰好达到完整张量展平后的矩阵秩。

<img src="reports/en/figures/proof_structure.png" alt="有限认证与展平秩预算共同迫使饱和秩型，再通过交叉因子恒等式导出矛盾。" width="900">

图中假设存在二元域上的 20 项分解；有限计算认证与后续代数推导分开表示。

本项工作提供三类相互关联的成果：

- **结构性证明机制**：有限几何迫使秩不等式取等，等号条件连接三个因子并导出矛盾。
- **可复验的有限前提**：八个商下界的编码、证书与独立检查路径支撑完整数学论证。
- **开放的研究过程**：经整理的 Meta-Trace 与研究材料呈现 Qiushi Engine 如何提出问题、
  形成方法、开展实验、修正判断，并逐步发展出证明。

经典矩阵几何和继承的商下界证书均在报告中注明来源。

## 研究记忆与轨迹

报告以不涉及私有部署的方式，简要介绍系统的研究、知识、记忆与工具能力，
并联系团队[首篇自主光学发现论文](https://arxiv.org/abs/2604.27092)。
本研究的数学工具环境包括 Python、C++、数值与符号计算、约束求解和精确证明检查。

**Meta-Trace 是 Qiushi Engine 记忆系统中的结构化研究历史。** 它连接历史摘要、
研究证据与方向变化，通过分层摘要和检索关联详细记录及材料，使后续研究能够
找回已有认识、成立条件与重要修正，复用方法并识别曾经纠正的错误。
公开版以原始 Meta-Trace 为依据，结合对应笔记、计划、程序与结果，按数学问题
归纳整合、压缩重复，保留实质纠错和未解决分支，而不是逐字公开运行日志。
附录 B 呈现连贯的研究脉络，[研究导读](research/guide.md)连接具体支撑材料。
读者既能理解证明如何形成，也能复用中间方法，带着已有证据继续研究开放问题。

## 研究如何推进

<img src="reports/en/figures/research_route.png" alt="构造与有限域两条研究线通过反馈改变表示，最终转向完整张量的结构性证明。" width="900">

1. 残差下降但系数增大，使研究区分数值抵消与有限系数的精确构造。
2. 合法支持集不等于完整分解，使研究追问第二、第三因子的兼容性。
3. 回到完整张量后，有限几何与秩预算共同迫使秩型 (16, 1, 3)。
4. 将“秩之和恰好为 27”理解为等号条件，得到交叉因子恒等式及最终矛盾。

各条研究路线、重要纠错、失败如何改变判断以及尚未解决的问题，均在附录 B 连贯保留。
研究过程的价值由这些具体决策及其证据体现，不以文件数量或运行时间代替。

公开的 **Research Trajectory（研究轨迹）本身也是一项贡献**：它把数学成果与
产生这一成果的证据积累、错误修正和表示变化联系起来。与可执行的证明包结合，
这份记录让 Qiushi Engine 的长程自主研究能力成为可以具体研究、比较和继续发展的对象。

以及向其他底域推广，是这一工作留下的后续问题。

## 实际使用

[Release 下载页](https://github.com/Oxelra-AI/Qiushi-Engine-Matmul-Research/releases/latest)
提供含实际证明数据的完整研究包、中英文 PDF，以及各自独立的 LaTeX 源码包。
使用 Git 时，先安装 Git LFS，再获取完整文件：

~~~sh
git lfs install
git clone https://github.com/Oxelra-AI/Qiushi-Engine-Matmul-Research.git
cd Qiushi-Engine-Matmul-Research
git lfs pull
make integrity
~~~

`make integrity` 只检查冻结输入的完整性，需要 Python 3.10 或更新版本，
不等于数学证明复验。安装[复验说明](reproducibility/README.md)中的依赖后，
`make verify` 重建占据约束并检查八份 DRAT 证明；完整复验还需要文档指定的上游验证器：

~~~sh
make verify-full
~~~

报告编译与数学复验相互独立：

~~~sh
make reports
make source-en
make source-zh
~~~

以上命令编译中英文完整 PDF，并生成各自的自包含 LaTeX 源码包。
`make reports-en` 或 `make reports-zh` 可单独编译一种语言。
数学复验不需要 Qiushi Engine 或模型调用。直接下载压缩包时，应选择 **Releases**
中的完整研究 ZIP，不应假定 GitHub 自动生成的源码压缩包包含 LFS 实体数据。
